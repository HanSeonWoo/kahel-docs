블로그 번역은 2025-08-12 최초 발표 당시의 설명을 보존합니다. 본문의 “최신 버전”, 지원 상태, 출시 예정 안내와 실험 기능 설정은 발표 당시 기준입니다.

주요 변경 사항

Android 16 지원

React Native 0.81로 빌드한 Android 앱은 이제 기본으로 Android 16(API 레벨 36)을 대상으로 합니다.

Google이 앞서 발표한 것처럼 Android 16에서는 앱이 화면 가장자리까지 표시되는 edge-to-edge 방식을 사용해야 합니다. 이 동작을 끄는 방법은 지원하지 않습니다.

이를 지원하기 위해 앞서 발표한 대로 <SafeAreaView> 컴포넌트를 사용 중단(deprecated) 상태로 지정합니다. edge-to-edge를 더 잘 지원하는 대안은 아래 설명을 확인하세요.

새 Gradle 속성 edgeToEdgeEnabled도 추가했습니다. 지원 대상인 Android 16 미만의 모든 버전에서 edge-to-edge를 켤지 선택할 수 있습니다.

Android 16을 대상으로 하는 앱에서는 예측 뒤로 가기 동작이 기본으로 켜집니다. 대부분의 경우 BackHandler API는 이전과 같이 작동합니다. 다만 onBackPressed() 메서드를 재정의하는 등 별도 네이티브 코드로 뒤로 가기를 처리한다면 코드를 직접 이전하거나 일시적으로 이 동작을 꺼야 할 수 있습니다. 업그레이드한 뒤 앱의 뒤로 가기 동작을 충분히 시험하세요.

Google은 이제 화면 방향이나 크기 제한과 관계없이 큰 화면 기기에서 적응형 레이아웃을 지원할 것을 요구합니다. 현재는 이 동작을 끌 수 있습니다. 그러나 Android 17 이전에 큰 화면에서 앱을 시험하고 반응형 UI로 수정할 것을 권장합니다.

2025년 11월 1일부터 Google Play에 제출하는 모든 앱은 네이티브 바이너리의 16KB 페이지 크기 요구 사항을 충족해야 합니다. Android 15 이상 기기를 대상으로 하는 새 앱과 업데이트에 적용됩니다. React Native는 이미 16KB 페이지 크기를 지원합니다. 앱의 모든 네이티브 코드와 외부 라이브러리도 이 요구 사항을 충족하는지 확인하세요.

Android 16의 변경 내용과 이전 절차는 discussions-and-proposals 저장소의 관련 글을 확인하세요.

SafeAreaView 사용 중단

내장 <SafeAreaView> 컴포넌트는 카메라 노치나 둥근 모서리 등을 피하여 화면의 안전 영역에 콘텐츠를 배치하도록 설계되었습니다. 그러나 iOS에서만 제한적으로 지원합니다. Android의 edge-to-edge 렌더링과 호환되지 않으며, 패딩 이외의 사용자 설정을 허용하지 않습니다. 따라서 많은 앱이 react-native-safe-area-context처럼 여러 플랫폼에서 유연하게 사용할 수 있는 방법을 선택했습니다.

React Native 0.81에서는 기존 <SafeAreaView>가 사용 중단 상태입니다. 앱에서 이 컴포넌트를 사용하면 React Native DevTools에 경고가 표시됩니다.

이 컴포넌트는 이후 React Native 버전에서 제거할 예정입니다. 모든 플랫폼에서 앱이 적절하게 표시되도록 react-native-safe-area-context 또는 유사한 라이브러리로 이전할 것을 권장합니다.

커뮤니티가 유지하는 JavaScriptCore 지원

지난해 발표한 것처럼 JavaScriptCore(JSC) 엔진 지원은 React Native와 별도로 배포하는 커뮤니티 패키지로 옮겼습니다. React Native 0.81에서는 내장 JavaScriptCore를 제거합니다. JavaScriptCore가 필요한 모든 앱은 0.81로 올릴 때 커뮤니티 패키지를 사용해야 합니다. 자세한 내용은 설치 안내를 확인하세요.

이 변경은 Hermes를 사용하는 앱에 영향을 주지 않습니다.

번역 참고

“지난해”는 원문의 표현입니다. 연결된 발표 글의 날짜는 2025-04-08입니다.

실험 기능 — 미리 컴파일한 iOS 빌드

React Native 0.81은 미리 컴파일한 iOS 빌드를 도입합니다. React Native가 주요 의존성인 프로젝트에서는 컴파일 시간이 최대 10분의 1로 줄어듭니다. Expo와 Meta가 함께 작업한 결과이며, React Native 0.80에서 제공한 작업을 확장합니다.

이 기능은 아직 실험 단계입니다. 이후 버전에서 모든 앱에 켤 수 있기를 기대합니다. 앱에서 미리 컴파일한 빌드를 시험하려면 pod install을 실행할 때 다음 환경 변수를 지정하세요.

RCT_USE_RN_DEP=1 RCT_USE_PREBUILT_RNCORE=1 bundle exec pod install

GitHub 토론에 의견을 남겨 주세요.

현재 다음 두 제한을 알고 있으며 해결하고 있습니다.

  • 미리 컴파일한 빌드에서는 React Native 내부 코드를 디버깅하거나 코드 안으로 단계별 실행을 할 수 없습니다. 앱에서 작성한 네이티브 코드는 계속 디버깅할 수 있습니다.
  • Xcode 26 Beta에서는 모든 대상을 Swift explicit modules를 켠 상태로 빌드하므로 사전 빌드를 지원하지 않습니다. Xcode 26에서 사용하려면 Xcode 프로젝트의 SWIFT_ENABLE_EXPLICIT_MODULES 플래그를 NO로 설정하세요. 이후 패치 버전에서 이 문제를 해결할 예정입니다.

이 기능의 자세한 설명은 Expo의 Precompiled React Native for iOS: Faster builds are coming in 0.81 글을 확인하세요.

호환성이 깨지는 변경

최소 Node.js 버전을 20으로 변경

이제 Node.js 20.19.4 이상이 필요합니다. 20.19.4는 글 작성 당시 최신 Maintenance LTS 버전입니다. React Native 0.81로 올릴 때 개발 환경이나 CI 환경의 Node.js도 올려야 할 수 있습니다.

최소 Xcode 버전을 16.1로 변경

이제 iOS 프로젝트를 빌드하려면 Xcode 16.1 이상이 필요합니다. React Native 0.81로 올릴 때 개발 환경이나 CI 환경의 Xcode도 올려야 할 수 있습니다.

Metro: Community CLI 프로젝트의 고급 설정 지원 개선

이제 React Native Community CLI 프로젝트의 metro.config.js에 지정한 resolveRequest와 getModulesRunBeforeMainModule 옵션을 Metro가 적용합니다. 이전에는 설정해도 작동하지 않았습니다. metro.config.js에 별도 값을 설정했다면 이전 동작을 복원하기 위해 해당 값을 삭제해야 할 수 있습니다.

처리하지 않은 JavaScript 오류의 보고 개선

React Native DevTools는 이제 처리하지 않은 JavaScript 오류의 원래 메시지와 스택 추적을 표시합니다. 오류에 원인(cause)이 있으면 함께 표시합니다. 컴포넌트에서 발생한 오류에는 소유자 스택(Owner Stack)도 표시합니다. 따라서 오류를 쉽게 디버깅하고 수정할 수 있습니다.

JavaScript 오류를 백엔드나 외부 오류 보고 서비스에 기록한다면 React Native 0.81로 올린 뒤 표시되는 로그가 달라질 수 있습니다. 예를 들어 이전에는 console.error로 보고하던 오류가 이제 발생한 예외로 더 많이 표시될 수 있습니다. 이에 맞게 백엔드의 일부 처리를 수정해야 할 수 있습니다.

RN_SERIALIZABLE_STATE와 C++ 플래그

이번 버전에는 새 아키텍처 컴포넌트의 직렬화 가능한 상태를 지원하는 RN_SERIALIZABLE_STATE 매크로를 도입했습니다.

라이브러리를 작성하며 별도 CMakeLists.txt 파일을 사용한다면 해당 파일에서 이 매크로를 지정해야 합니다. 지정하지 않으면 C++ 코드의 컴파일이 실패할 수 있습니다.

이를 지원하기 위해 새 CMake 함수 target_compile_reactnative_options를 도입했습니다. 이 함수가 매크로와 필요한 모든 C++ 플래그를 설정합니다. CMakeLists 파일에서 다음과 같이 호출할 수 있습니다.

target_compile_reactnative_options(myLibraryName PRIVATE)

react-native-screens에서 이 매크로를 설정한 예제를 확인할 수 있습니다.

이 변경은 고급 기능을 사용하는 복잡한 라이브러리에만 영향을 줍니다. Codegen을 사용하고 별도 CMake 파일이 없는 라이브러리는 영향을 받지 않습니다.

그 외 호환성이 깨지는 변경

다음은 제품 코드에 작은 영향을 줄 수 있다고 판단한 추가 변경 사항입니다.

Android

  • 아래 클래스를 내부 전용으로 변경했습니다. 공개 API가 아니므로 사용하지 않아야 합니다. 영향을 받는 라이브러리에는 이미 알리거나 수정안을 제출했습니다.
    • com.facebook.react.fabric.mounting.MountingManager
    • com.facebook.react.views.text.TextLayoutManager
  • textAlignVertical 네이티브 속성을 TextAttribute.h에서 ParagraphAttribute.h로 옮겼습니다.
    • 이 속성은 가장 바깥쪽 텍스트 뷰인 문단 뷰에만 영향을 줍니다. 그러나 텍스트 속성에 포함되어 있었습니다. 플랫폼의 제한을 정확히 반영하도록 문단 속성으로 옮겼습니다.
    • 이 변경은 <Text> 컴포넌트의 JavaScript API에 영향을 주지 않습니다.
    • C++ Text API와 상호 작용하는 Fabric 컴포넌트를 구현한 경우에만 영향을 받습니다.
    • 영향을 받는다면 코드의 TextAttributes.h를 ParagraphAttribute.h로 바꿀 수 있습니다.

호환성이 깨지는 변경의 전체 목록은 0.81 CHANGELOG를 확인하세요.

0.81로 업그레이드하기

기존 프로젝트에서는 React Native Upgrade Helper로 버전 간 코드 변경을 확인하세요. 업그레이드 문서도 함께 확인하세요.

새 프로젝트를 만들려면 다음 명령을 사용하세요.

npx @react-native-community/cli@latest init MyProject --version latest

Expo를 사용한다면 출시 예정인 Expo SDK 54에서 React Native 0.81을 기본 React Native 버전으로 지원할 예정입니다.

0.81.6 · Codegen·에셋·기존 아키텍처 수정과 iOS 입력 처리 개선

GitHub 배포: 2026-02-07 02:30:29 · npm 게시: 2026-02-06 02:38:24 (모두 UTC+9)

GitHub 릴리스 본문에는 변경 항목이 없습니다. 아래 다섯 항목은 공식 CHANGELOG에서 확인했습니다. 직전 정식 태그와도 비교했습니다.

  • 에셋: 에셋 URL의 unstable_path 쿼리 매개변수를 처리합니다.
  • Codegen: generate-artifacts-executor에서 선택적 출력 경로를 처리하도록 수정했습니다.
  • Android / 기존 아키텍처: Metro에서 새로 고침할 때 앱이 멈추는 문제를 수정했습니다.
  • iOS / Codegen: Xcode 스크립트 단계에서 iOS 산출물 생성기를 실행할 때 출력이 잘못되는 문제를 수정했습니다.
  • iOS / 이벤트: 동시에 추적할 수 있는 포인터의 최대 수를 17개로 늘렸습니다.

다음 내용은 직전 정식 태그와의 공식 비교에서 확인한 내용입니다.

  • React와 @types/react의 peer dependency를 ^19.1.0에서 ^19.1.4로 올렸습니다.
  • Android 15 이상에서 텍스트가 잘리는 문제의 수정 커밋을 추가한 뒤 되돌렸습니다. 따라서 그 수정은 최종 패치에 포함된 변경으로 계산하지 않았습니다.
  • 태그 사이에는 총 10개 커밋이 있습니다. 내부 Podfile.lock과 배포 버전 정보도 갱신했습니다.

GitHub 릴리스에는 여섯 항목이 있습니다. main CHANGELOG는 그중 Switch, Android 권한, iOS RCTDeviceInfo 세 항목만 기록합니다. 아래 목록은 공식 릴리스의 전체 항목을 보존합니다.

  • Android / 권한: Android 16에서 권한 요청이 항상 완료되지 않던 문제를 수정했습니다.
  • Android / 텍스트: ReactTextViewManager를 상속할 수 있게 했습니다.
  • Android / 변환: 뷰의 초기 크기가 0일 때 변환(transform)이 잘못 표현되는 문제를 수정했습니다.
  • iOS / 기기 정보: 현대적인 iOS 앱 구조에서 application.delegate.window가 nil이면 발생하던 RCTDeviceInfo 앱 종료 문제를 수정했습니다.
  • iOS / 기존 아키텍처: Switch의 동작을 수정했습니다.
  • iOS / 사전 빌드: GNU coreutils의 cp 명령을 사용할 때 사전 컴파일 바이너리 때문에 컴파일이 실패하던 문제를 수정했습니다.

0.81.1 · Xcode 26 사전 빌드, 접근성, iOS 입력·심볼 처리 수정

GitHub 배포: 2025-09-01 19:21:25 · npm 게시: 2025-08-28 01:04:13 (모두 UTC+9)

  • iOS / 사전 빌드: 미리 컴파일한 빌드를 사용할 때 SWIFT_ENABLE_EXPLICIT_MODULES=NO를 설정하여 Xcode 26을 지원합니다.
  • 빌드 도구: 빠진 Babel 의존성을 추가했습니다.
  • 접근성: TextInput의 aria-label을 수정했습니다.
  • iOS / TextInput: maxLength를 0으로 설정하면 입력을 올바르게 차단합니다.
  • iOS / Switch: iOS 26에서 레이아웃이 작동하도록 수정했습니다.
  • iOS / C++: USE_FRAMEWORKS를 사용할 때 RuntimeExecutor.h 포함 경로를 수정했습니다.
  • iOS / 빌드 스크립트: 공백이 있는 경로를 처리하도록 수정했습니다.
  • iOS / 사전 빌드: ReactNativeDependencies의 Symbols 폴더를 복사하고 빌드하는 방식을 수정했습니다.
  • iOS / 사전 빌드: React.xcframework를 사용할 때 잘못된 JSI 심볼이 선택되는 문제를 수정했습니다.
  • iOS / 사전 빌드: ReactNativeDependencies.xcframework를 미리 컴파일할 때 번들을 올바르게 복사합니다.
  • iOS / 사전 빌드: React.xcframework의 Symbols 폴더 구성을 ReactNativeDependencies.xcframework와 맞췄습니다.
  • iOS / 사전 빌드: ReactNativeDependencies.podspec에서 발생하던 파일이 이미 있다는 오류를 수정했습니다.
  • iOS / 사전 빌드: ReactCodegen을 명시적으로 처리하도록 추가했습니다.
