블로그 번역은 2025-04-08 최초 발표 당시의 설명을 보존합니다. 본문의 “최신 버전”, 지원 상태, 출시 예정 안내와 실험 기능 설정은 발표 당시 기준입니다.

현재 조사 결과는 0.79.x 패치 내역과 사전 배포 기록에 별도로 표시했습니다. 확인한 가장 최근 정식 패치는 0.79.7입니다.

오늘 React Native 0.79를 배포합니다.

이번 버전은 여러 영역의 성능 개선과 버그 수정을 제공합니다. 먼저 Metro는 해시 계산을 늦추는 방식으로 시작 속도를 높였으며, package exports를 안정 기능으로 지원합니다. JavaScript 번들 압축 방식의 변경으로 Android 앱의 시작 시간도 줄어듭니다. 그 외 여러 변경도 포함됩니다.

주요 변경 사항

Metro: 더 빠른 시작과 package exports 지원

이번 버전에는 Metro 0.82가 포함됩니다. 해시 계산을 필요한 시점까지 늦추어 첫 yarn start의 실행 속도를 보통 3배 이상 높입니다. 큰 프로젝트와 모노레포에서는 개선 폭이 더 큽니다. 따라서 일상적인 개발과 CI 빌드가 빨라집니다.

Metro 0.82에서는 package.json의 "exports"와 "imports" 필드 해석을 안정 기능으로 전환합니다. "exports" 해석은 React Native 0.72에서 도입했습니다. "imports" 지원은 커뮤니티 기여로 추가되었습니다. 이제 두 기능은 React Native 0.79의 모든 프로젝트에서 기본으로 켜집니다.

현대적인 npm 의존성과의 호환성이 높아집니다. 표준에 맞는 새로운 방식으로 프로젝트를 구성할 수도 있습니다.

주의 · 호환성이 깨지는 변경

커뮤니티에서 package.json의 "exports"를 한동안 시험했지만, 이번 전환은 일부 패키지와 프로젝트 설정에서 호환성을 깨뜨릴 수 있습니다.

특히 Firebase와 AWS Amplify를 포함한 널리 사용하는 일부 패키지의 호환성 문제를 보고받았습니다. 해당 패키지에서 문제를 수정하도록 작업하고 있습니다.

문제가 발생하면 다음 방법을 사용하세요.

  • Metro 0.81.5 긴급 수정 버전으로 갱신하거나, resolver.unstable_enablePackageExports = false로 설정하여 기능을 끄세요.
  • 영향을 받는 패키지와 이후 변경은 expo/expo#36551을 확인하세요.

JSC를 커뮤니티 패키지로 이전

React Native의 API 범위를 줄이는 작업의 일부로 JavaScriptCore(JSC) 엔진을 커뮤니티가 유지하는 @react-native-community/javascriptcore 패키지로 옮기고 있습니다.

이 변경은 Hermes 사용자에게 영향을 주지 않습니다.

React Native 0.79부터 README의 설치 안내에 따라 커뮤니티가 지원하는 JSC를 사용할 수 있습니다. React Native 코어에서 제공하는 JSC도 0.79에서 계속 사용할 수 있습니다. 다만 가까운 시일 안에 제거할 계획입니다.

JSC를 커뮤니티 패키지로 옮기면 버전을 더 자주 갱신하고 최신 기능을 제공할 수 있습니다. 커뮤니티 JSC는 React Native와 별도의 배포 일정을 따릅니다.

iOS: Swift와 호환되는 네이티브 모듈 등록

이번 버전에서는 네이티브 모듈을 React Native 런타임에 등록하는 방식을 바꿉니다. 새 방식은 공식 문서에 설명된 컴포넌트 등록 방식을 따릅니다.

이번 버전부터 package.json을 수정하여 모듈을 등록할 수 있습니다. ios 속성에 새 필드 modulesProvider를 도입했습니다.

package.json — 추가한 줄은 +로 표시
"codegenConfig": {
     "ios": {
+       "modulesProvider": {
+         "JS Name for the module": "ObjC Module provider for the pure C++ TM or a class conforming to RCTTurboModule"
+     }
    }
}

예제의 키는 모듈의 JavaScript 이름입니다. 값은 순수 C++ TurboModule의 Objective-C 모듈 제공자 또는 RCTTurboModule을 따르는 클래스입니다.

Codegen은 package.json을 바탕으로 필요한 모든 코드를 생성합니다.

순수 C++ 네이티브 모듈을 사용한다면 다음 권장 설정을 적용해야 합니다.

앱에서 순수 C++ 네이티브 모듈 설정

순수 C++ 네이티브 모듈에는 모듈과 나머지 앱을 연결하는 새 Objective-C++ 클래스가 필요합니다.

CppNativeModuleProvider.h
#import <Foundation/Foundation.h>
#import <ReactCommon/RCTTurboModule.h>

NS_ASSUME_NONNULL_BEGIN

@interface <YourNativeModule>Provider : NSObject <RCTModuleProvider>

@end
CppNativeModuleProvider.mm
NS_ASSUME_NONNULL_END

#import "<YourNativeModule>Provider.h"
#import <ReactCommon/CallInvoker.h>
#import <ReactCommon/TurboModule.h>
#import "<YourNativeModule>.h"

@implementation NativeSampleModuleProvider

- (std::shared_ptr<facebook::react::TurboModule>)getTurboModule:
    (const facebook::react::ObjCTurboModule::InitParams &)params
{
  return std::make_shared<facebook::react::NativeSampleModule>(params.jsInvoker);
}

두 파일의 매크로 위치와 예제 클래스 이름은 공식 원문의 표기를 보존했습니다.

이 새 방식으로 앱 개발자와 라이브러리 관리자의 네이티브 모듈 등록 방법을 통일했습니다. 라이브러리도 package.json에 같은 속성을 지정하면 Codegen이 나머지 작업을 처리합니다.

이 방식은 0.77에서 도입된 제한도 해결합니다. 당시에는 Swift AppDelegate에서 순수 C++ 네이티브 모듈을 등록할 수 없었습니다. 위 변경은 AppDelegate를 수정하지 않습니다. 생성된 코드는 Swift와 Objective-C로 구현한 AppDelegate 모두에서 작동합니다.

Android: 더 빠른 앱 시작

Android의 시작 시간을 크게 줄이는 변경도 제공합니다.

이번 버전부터 APK 안의 JavaScript 번들을 더 이상 압축하지 않습니다. 이전에는 앱을 시작하기 전에 Android 시스템이 JavaScript 번들의 압축을 풀어야 했습니다. 이 작업 때문에 앱 시작이 크게 느려졌습니다.

이번 버전부터는 기본으로 압축하지 않은 JavaScript 번들을 제공합니다. 따라서 Android 앱이 전반적으로 더 빨리 시작합니다.

Margelo 팀은 Discord 앱에서 이 기능을 시험하여 큰 성능 개선을 확인했습니다. 코드 한 줄을 바꾸어 Discord의 상호 작용 가능 시점까지의 시간(TTI)을 400ms 줄였습니다. 12%의 속도 개선이며 Samsung A14에서 시험한 결과입니다.

반면 번들을 압축하지 않고 저장하면 사용자 기기에서 앱이 차지하는 저장 공간이 늘어납니다. 저장 공간이 중요하다면 app/build.gradle의 enableBundleCompression 속성으로 이 동작을 선택할 수 있습니다.

app/build.gradle
react {
  // ...
  // JS 번들을 압축하려면 true로 설정합니다.
  // 시작은 느리지만 저장 공간을 적게 사용합니다.
  enableBundleCompression = true
  // JS 번들을 압축하지 않으려면 false로 설정합니다.
  // 시작은 빠르지만 저장 공간을 더 사용합니다.
  enableBundleCompression = false

  // 기본값은 false입니다.
}

이번 버전에서는 APK 크기가 커집니다. 그러나 네트워크에서 APK를 내려받을 때는 압축하므로 사용자의 APK 다운로드 크기는 추가로 늘어나지 않습니다.

호환성이 깨지는 변경

원격 JavaScript 디버깅 제거

디버깅을 개선하는 작업의 일부로 Chrome을 통한 원격 JavaScript 디버깅을 제거합니다. 이 기존 방식은 사용 중단 상태였으며, React Native 0.73에서 실행 중 선택하여 켜는 방식으로 바뀌었습니다. 현대적이고 안정적인 디버깅을 위해 React Native DevTools를 사용하세요.

이에 따라 React Native는 커뮤니티 프로젝트 react-native-debugger와 더 이상 호환되지 않습니다. Redux DevTools 같은 외부 디버깅 확장을 사용하려면 Expo DevTools Plugins를 사용하거나 해당 도구의 독립 실행 버전을 통합할 것을 권장합니다.

자세한 설명은 별도 글을 확인하세요.

내부 모듈을 export 문법으로 변경

JavaScript 코드를 현대화하는 작업의 일부로 react-native의 여러 구현 모듈을 수정했습니다. module.exports 대신 export 문법을 일관되게 사용하도록 바꿨습니다.

총 약 46개 API를 갱신했습니다. 전체 목록은 변경 기록에서 확인할 수 있습니다.

이 변경은 기존 가져오기 방식에 작은 영향을 줍니다.

경우 1: 기본 내보내기 
  // 변경됨 — require() 문법
- const ImageBackground = require('react-native/Libraries/Image/ImageBackground');
+ const ImageBackground = require('react-native/Libraries/Image/ImageBackground').default;

// 변경 없음 — import 문법
import ImageBackground from 'react-native/Libraries/Image/ImageBackground';

// 권장 — 루트 경로에서 가져오기
import {ImageBackground} from 'react-native';
경우 2: 추가 내보내기

이 패턴은 매우 적습니다. 이 경우도 루트 'react-native' 경로에서 가져오면 영향을 받지 않습니다.

  // 변경 없음 — require() 문법
  const BlobRegistry = require('react-native/Libraries/Blob/BlobRegistry');

  // 변경 없음 — 구조 분해를 사용하는 require() 문법
  const {register, unregister} = require('react-native/Libraries/Blob/BlobRegistry');

  // 변경됨 — 객체 하나로 가져오는 import 문법
- import BlobRegistry from 'react-native/Libraries/Blob/BlobRegistry';
+ import * as BlobRegistry from 'react-native/Libraries/Blob/BlobRegistry';


  // 변경 없음 — 구조 분해를 사용하는 import 문법
  import {register, unregister} from 'react-native/Libraries/Blob/BlobRegistry';

  // 권장 — 루트 경로에서 가져오기
  import {BlobRegistry} from 'react-native';

이 변경의 영향은 매우 작을 것으로 예상합니다. 특히 TypeScript와 import 문법을 사용하는 프로젝트는 영향이 적습니다. 타입 오류를 확인하고 필요한 코드를 수정하세요.

권장 · 루트 react-native 경로에서 가져오기

이후 불필요한 호환성 변경을 피하려면 루트 'react-native' 경로에서 가져올 것을 적극 권장합니다. 다음 버전에서는 React Native의 공개 JavaScript API를 더 명확하게 정의하는 작업의 일부로 deep import를 사용 중단 상태로 지정할 예정입니다(RFC 참고).

그 외 호환성이 깨지는 변경

다음은 제품 코드에 작은 영향을 줄 수 있다고 판단한 추가 변경 사항입니다.

  • 박스 그림자와 필터의 단위 없는 길이: CSS와 웹 명세에 더 잘 맞도록 box-shadow와 filter에서 단위 없는 길이를 더 이상 지원하지 않습니다. 예를 들어 1 1 black인 box-shadow는 렌더링하지 않습니다. 대신 1px 1px black처럼 단위를 지정해야 합니다.
  • normalize-color에서 잘못된 hwb() 문법 지원 제거: CSS와 웹 명세에 맞도록 hwb()의 일부 잘못된 문법을 제한합니다. 이전에는 쉼표로 구분한 값인 hwb(0, 0%, 100%)도 지원했지만, 이제는 지원하지 않습니다. hwb(0 0% 100%)로 이전해야 합니다. 자세한 내용은 관련 변경을 확인하세요.
  • Libraries/Core/ExceptionsManager의 내보내기 변경: React Native JavaScript API를 현대화하는 작업의 일부로 ExceptionsManager를 변경했습니다. 이제 ExceptionsManager 객체를 기본으로 내보내고, SyntheticError를 추가 항목으로 내보냅니다.

감사의 말

React Native 0.79에는 100명의 기여자가 만든 944개 이상의 커밋이 포함됩니다. 모든 분의 작업에 감사드립니다.

이번 버전에 중요한 기여를 한 다음 커뮤니티 구성원에게 감사드립니다.

  • Marc Rousavy: Android 앱 시작 속도 개선 기능의 개발과 설명 작성.
  • Kudo Chien, Oskar Kwaśniewski: @react-native-community/javascriptcore 패키지 작업과 JSC 커뮤니티 패키지 이전 설명 작성.
  • James Lawson: Metro의 import 하위 경로 해석 지원 추가.

이 배포 글에서 기능을 설명한 추가 작성자에게도 감사드립니다.

  • Rob Hogan: 새 Metro 기능 설명.
  • Alex Hunt: 원격 JavaScript 디버깅 제거와 내부 모듈의 export 문법 변경 설명.
  • Riccardo Cipolleschi: iOS 네이티브 모듈 등록 작업.

0.79로 업그레이드하기

기존 프로젝트에서는 React Native Upgrade Helper로 버전 간 코드 변경을 확인하세요. 업그레이드 문서도 함께 확인하세요.

새 프로젝트를 만들려면 다음 명령을 사용하세요.

npx @react-native-community/cli@latest init MyProject --version latest

Expo를 사용한다면 출시 예정인 Expo SDK 53에서 React Native 0.79를 기본 React Native 버전으로 지원할 예정입니다.

발표 당시 지원 버전

참고 · 2025-04-08 발표 기준

이제 0.79가 React Native의 최신 안정 버전이며, 0.76.x는 지원 종료(unsupported) 상태가 됩니다. 자세한 내용은 React Native 지원 정책을 확인하세요. 가까운 시일 안에 0.76의 마지막 지원 종료 업데이트를 배포할 예정입니다.

0.79.x 패치 릴리스

확인일: 2026-10-06 · 배포일: 한국 시간(UTC+9) · RC와 nightly는 정식 패치에서 제외

공식 GitHub Releases, 전체 v0.79. 태그, CHANGELOG-0.7x.md와 npm 배포 기록을 함께 확인했습니다. 최초 정식 버전 0.79.0의 GitHub 공개일은 2025-04-08입니다. 정식 패치는 7개입니다. 조사 시점에 0.79.8 이상의 정식 태그나 배포 기록은 없습니다.

표의 배포일은 기존 문서와 같이 GitHub Release의 published_at을 한국 시간으로 바꾼 날짜입니다. npm 패키지 게시 시각은 GitHub 공개 시각과 다를 수 있으므로 각 버전에 함께 표시합니다.

main의 CHANGELOG.md는 0.79 상세 항목을 별도 CHANGELOG-0.7x.md로 연결합니다. 이 문서는 그 상세 파일을 확인했습니다.
