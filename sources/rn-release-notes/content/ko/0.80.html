블로그 번역은 2025-06-12 최초 발표 당시의 설명을 보존합니다. 본문의 “최신 버전”, 지원 상태, 출시 예정 안내와 실험 기능 설정은 발표 당시 기준입니다.

현재 조사 결과는 0.80.x 패치 내역과 사전 배포 기록에 별도로 표시했습니다. 확인한 가장 최근 정식 패치는 0.80.3입니다.

오늘 React Native 0.80을 배포합니다.

이번 버전은 React Native에 포함되는 React를 발표 당시 최신 안정 버전인 19.1.0으로 올립니다.

JavaScript API의 안정성을 높이는 변경도 제공합니다. 내부 경로에서 가져오는 deep import는 이제 경고를 표시합니다. 또한 더 정확하고 안전한 타입을 제공하는 새 Strict TypeScript API를 선택하여 사용할 수 있습니다.

React Native의 기존 아키텍처는 이제 공식적으로 개발을 동결합니다. 기존 아키텍처의 지원을 완전히 종료하면 작동하지 않을 API에 대한 경고도 표시됩니다.

주요 변경 사항

JavaScript deep import 사용 중단

이번 버전에서는 React Native의 공개 JavaScript API를 개선하고 안정화하는 작업을 시작합니다. 첫 단계는 앱과 프레임워크에서 가져올 수 있는 API의 범위를 더 명확하게 정하는 것입니다. 이에 따라 React Native의 deep import를 공식적으로 사용 중단(deprecated) 상태로 지정하고(RFC 참고), ESLint와 JavaScript 콘솔에 경고를 추가합니다.

이 경고는 프로젝트 소스 코드에서 가져오는 항목에만 적용합니다. 경고를 끌 수도 있습니다. 다만 이후 버전에서 React Native API의 deep import를 제거할 예정입니다. 따라서 패키지의 루트 경로에서 가져오도록 수정해야 합니다.

// 변경 전 — 내부 경로에서 가져오기
import {Alert} from 'react-native/Libraries/Alert/Alert';

// 변경 후 — react-native에서 가져오기
import {Alert} from 'react-native';

일부 API는 루트 경로에서 내보내지 않습니다. deep import가 없어지면 이런 API는 사용할 수 없게 됩니다. 이는 React Native API의 전체 범위를 줄이기 위한 의도적인 변경입니다. 사용자 문제를 받는 의견 수집 토론을 열었습니다. 최소한 다음 두 번의 React Native 배포에 걸쳐 커뮤니티와 함께 내보낼 API를 확정할 예정입니다. 의견을 공유해 주세요.

자세한 설명은 Moving Towards a Stable JavaScript API 글을 확인하세요.

선택 기능 — Strict TypeScript API

위와 같이 공개 API의 내보내기 범위를 다시 정의하면서, 0.80의 react-native 패키지에 새 TypeScript 타입도 제공합니다. 이 타입을 Strict TypeScript API라고 부릅니다.

Strict TypeScript API를 선택하면 앞으로 제공할 React Native의 안정 JavaScript API를 미리 사용할 수 있습니다. 새 타입에는 다음 특징이 있습니다.

  1. 소스 코드에서 직접 생성합니다. 타입이 적용되는 범위와 정확성을 높이므로 더 강한 호환성 보장을 기대할 수 있습니다.
  2. React Native의 index 파일로 범위를 제한합니다. 공개 API를 더 명확하게 정의하므로 내부 파일을 변경해도 API가 깨지지 않습니다.

기존 타입과 함께 제공하므로 준비가 되었을 때 이전할 수 있습니다. 표준 React Native API를 사용하는 많은 앱은 코드를 바꾸지 않고 검사를 통과할 수 있습니다. 먼저 새 기능을 적용하려는 사용자와 새 앱에는 tsconfig.json에서 이 기능을 선택할 것을 적극 권장합니다.

커뮤니티가 준비되면 이후 버전에서 Strict TypeScript API를 기본 API로 전환합니다. 이 전환은 deep import 제거와 같은 시점에 진행할 예정입니다.

자세한 설명은 Moving Towards a Stable JavaScript API 글을 확인하세요.

기존 아키텍처 개발 동결과 경고

React Native의 새 아키텍처는 0.76부터 기본 선택입니다. 여러 프로젝트와 도구가 새 아키텍처에서 큰 이점을 얻었다는 성공 사례도 확인했습니다.

최근 공유한 것처럼 기존 아키텍처는 이제 개발을 동결한 상태로 봅니다. 기존 아키텍처의 새 버그 수정이나 기능을 더 이상 개발하지 않습니다. 배포를 준비할 때 기존 아키텍처를 시험하는 작업도 중단합니다.

원활하게 이전할 수 있도록 버그나 이전보다 나빠진 동작이 발생하면 새 아키텍처를 끄는 선택을 계속 허용합니다.

그러나 React Native에 두 아키텍처를 함께 제공하는 일은 매우 어렵습니다. 실행 성능, 앱 크기, 코드 유지 관리에 영향을 줍니다.

따라서 이후 어느 시점에는 기존 아키텍처의 지원을 종료해야 합니다.

0.80에는 새 아키텍처에서 작동하지 않을 API를 사용하면 React Native DevTools에 표시되는 경고를 추가했습니다.

이 경고를 무시하지 말고, 이후 변경에 대비하여 앱과 라이브러리를 새 아키텍처로 이전할 것을 권장합니다.

자세한 설명은 최근 App.js에서 발표한 Life After Legacy: The New Architecture Future 영상을 확인하세요.

React 19.1.0

이번 React Native 버전에는 발표 당시 최신 React 안정 버전인 19.1.0이 포함됩니다.

React 19.1.0의 모든 새 기능과 버그 수정은 배포 설명에서 확인할 수 있습니다.

주의

React 19.1.0의 주요 기능 중 하나는 소유자 스택(Owner Stack)의 구현과 개선입니다. 개발할 때만 사용하는 기능이며, 특정 오류를 일으킨 컴포넌트를 확인하는 데 도움이 됩니다.

그러나 React Native Babel Preset에서 기본으로 켜는 @babel/plugin-transform-function-name 플러그인을 사용하면 React Native의 소유자 스택이 예상대로 작동하지 않는 것을 알고 있습니다. 이후 React Native 버전에서 이 문제를 수정할 예정입니다.

실험 기능 — React Native iOS 의존성 사전 빌드

React Native iOS 앱을 빌드한다면 첫 네이티브 빌드에 시간이 걸리는 것을 보았을 것입니다. 보통 몇 분이 걸리며, 오래된 컴퓨터에서는 더 오래 걸릴 수 있습니다. React Native의 전체 iOS 코드와 모든 의존성을 컴파일해야 하기 때문입니다.

최근 몇 주 동안 Android와 유사하게 iOS용 React Native 코어의 일부를 미리 빌드하는 방법을 시험했습니다. React Native 앱을 처음 실행할 때의 빌드 시간을 줄이는 것이 목적입니다.

React Native 0.80은 iOS용 React Native의 일부를 사전 빌드 형태로 제공할 수 있는 첫 버전입니다.

React Native 배포 과정에서 ReactNativeDependencies.xcframework라는 XCFramework를 만듭니다. React Native가 의존하는 외부 라이브러리만 미리 빌드한 파일입니다.

이 초기 iOS 사전 빌드가 절약하는 시간을 시험하고 측정했습니다. M4 컴퓨터에서 수행한 측정에서는 소스에서 빌드할 때보다 iOS 빌드가 약 12% 더 빨랐습니다.

사용자 버그 보고 중 일부는 React Native의 외부 의존성 빌드 문제에서 발생하는 것도 확인했습니다. 예를 들어 #39568이 있습니다. 외부 의존성을 대신 빌드하여 제공하면 사용자가 이런 빌드 문제를 겪지 않게 할 수 있습니다.

React Native 전체를 미리 빌드하는 것은 아닙니다. Folly와 GLog처럼 Meta가 직접 관리하지 않는 라이브러리만 미리 빌드합니다.

이후 버전에서는 나머지 React Native 코어도 사전 빌드로 제공할 예정입니다.

사용 방법

이 기능은 아직 실험 단계이므로 기본으로 켜지지 않습니다.

사용하려면 환경 변수 RCT_USE_RN_DEP를 추가하여 pod를 설치하세요.

RCT_USE_RN_DEP=1 bundle exec pod install

프로젝트에서 작업하는 모든 개발자에게 적용하려면 Podfile을 다음과 같이 수정할 수도 있습니다.

Podfile — 추가한 줄은 +로 표시
if linkage != nil
  Pod::UI.puts "Configuring Pod with #{linkage}ally linked Frameworks".green
  use_frameworks! :linkage => linkage.to_sym
end

+ENV['RCT_USE_RN_DEP'] = '1'

target 'HelloWorld' do
  config = use_native_modules!

사전 빌드로 인해 사용자나 앱에 문제가 발생하면 이 토론에 알려 주세요. 문제를 조사하고 앱이 사전 빌드 여부와 관계없이 같은 방식으로 작동하도록 하겠습니다.

기타 변경 사항

Android: IPO로 APK 크기 감소

이번 버전은 React Native로 빌드한 모든 Android 앱의 크기를 크게 줄입니다. 0.80부터 React Native와 Hermes 빌드 모두에서 프로시저 간 최적화(IPO)를 켰습니다.

그 결과 모든 Android 앱에서 약 1MB를 절약했습니다.

React Native 버전을 0.80으로 올리면 이 크기 감소 효과를 얻습니다. 프로젝트에서 추가로 변경할 내용은 없습니다.

새 앱 시작 화면 디자인 변경

Expo 대신 Community CLI와 Template을 사용한다면 이번 버전에서 새 앱 시작 화면이 별도 패키지로 옮겨지고 디자인도 바뀐 것을 볼 수 있습니다. Community Template으로 새 앱을 만들 때 초기 반복 코드를 줄입니다. 큰 화면에서도 더 나은 사용 환경을 제공합니다.

JSC 커뮤니티 지원 안내

React Native 0.80은 React Native가 직접 JSC를 지원하는 마지막 버전입니다. 이후 JSC 지원은 커뮤니티가 유지하는 @react-native-community/javascriptcore 패키지로 제공합니다.

이 발표를 보지 못했다면 관련 설명을 확인하세요.

호환성이 깨지는 변경

주 패키지에 "exports" 필드 추가

안정 JavaScript API 작업의 일부로 react-native의 package.json에 "exports" 필드를 추가했습니다.

0.80에서는 이 매핑이 기본으로 모든 JavaScript 하위 경로를 계속 공개합니다. 따라서 큰 호환성 문제를 일으키지는 않을 것으로 예상합니다. 다만 react-native 패키지 내부 모듈을 찾는 방식이 일부 달라질 수 있습니다.

  • Metro에서는 "exports"에 일치하는 경로에 플랫폼별 확장자를 자동으로 적용하지 않습니다. 이 동작에 대응하는 여러 호환 모듈을 제공했습니다(#50426).
  • Jest에서는 deep import를 모의 객체로 대체하는 방식이 달라질 수 있습니다. 이에 따라 테스트를 수정해야 할 수 있습니다.

그 외 호환성이 깨지는 변경

다음은 제품 코드에 작은 영향을 줄 수 있다고 판단한 추가 변경 사항입니다.

JavaScript

  • eslint-plugin-react-hooks를 4.6.0에서 5.2.0으로 올렸습니다. 전체 내용은 변경 기록을 확인하세요. react-hooks 검사 규칙이 새로운 오류를 표시할 수 있으므로 수정하거나 해당 오류 표시를 꺼야 합니다.

Android

  • React Native에 포함되는 Kotlin을 2.1.20으로 올렸습니다. Kotlin 2.1에는 모듈이나 컴포넌트에서 시험할 수 있는 새 언어 기능이 포함됩니다. 자세한 내용은 공식 배포 안내를 확인하세요.
  • 0.73부터 사용 중단 상태였던 StandardCharsets 클래스를 삭제했습니다. 대신 java.nio.charset.StandardCharsets를 사용하세요.
  • 아래 클래스를 내부 전용으로 변경했습니다. 공개 API가 아니므로 사용하지 않아야 합니다. 영향을 받는 라이브러리에는 이미 알리거나 수정안을 제출했습니다.
    • com.facebook.react.fabric.StateWrapperImpl
    • com.facebook.react.modules.core.ChoreographerCompat
    • com.facebook.react.modules.common.ModuleDataCleaner
  • 아래 클래스를 Java에서 Kotlin으로 옮겼습니다. 사용 중이라면 일부 매개변수의 null 허용 여부와 타입이 달라졌으므로 코드를 수정해야 할 수 있습니다.
    • com.facebook.react.devsupport의 모든 클래스
    • com.facebook.react.bridge.ColorPropConverter
    • com.facebook.react.views.textinput.ReactEditText
    • com.facebook.react.views.textinput.ReactTextInputManager

iOS

  • RCTUtils.h의 RCTFloorPixelValue를 삭제했습니다. React Native에서 사용하지 않던 메서드이므로 완전히 제거했습니다.

추가로 작은 호환성 변경은 0.80 CHANGELOG에 있습니다.

감사의 말

이번 버전에 중요한 기여를 한 다음 커뮤니티 구성원에게 특별히 감사드립니다.

0.80.3 · 마지막 0.80 패치 — Android 안정성·접근성과 iOS 입력·새로 고침 수정

GitHub 배포: 2026-01-28 18:49:16 · npm 게시: 2026-01-27 05:24:05 (모두 UTC+9)

공식 릴리스는 이 버전이 마지막 0.80 배포이며 0.80의 지원이 종료되었다고 안내합니다. 아래 항목은 공식 릴리스와 CHANGELOG에서 확인했습니다. 직전 정식 태그와도 비교했습니다.

  • Codegen: 빠진 의존성을 수정했습니다.
  • Android / 접근성: TalkBack의 사용자 지정 접근성 작업 ID를 안정적으로 유지하도록 수정했습니다.
  • Android / 빌드: Codegen 라이브러리의 소스가 누락되는 실행 순서 문제를 수정했습니다.
  • Android / HeadlessJsTaskService: 접근자 메서드를 다시 open으로 지정했습니다.
  • Android / 기존 아키텍처: Metro에서 새로 고침할 때 앱이 멈추는 문제를 수정했습니다.
  • Android / 권한: Android 16에서 권한 요청이 항상 완료되지 않던 문제를 수정했습니다.
  • Android / View: RootView를 다시 만들 때 글꼴 배율을 갱신합니다.
  • iOS / 사전 빌드: GNU coreutils의 cp 명령과 호환되도록 수정했습니다.
  • iOS / RefreshControl: 컴포넌트 재사용 처리를 수정했습니다.
  • iOS / RefreshControl: 처음 마운트할 때 새로 고침 상태가 표시되지 않던 문제를 수정했습니다.
  • iOS / RCTDeviceInfo: application.delegate.window가 nil이면 발생하던 앱 종료 문제를 수정했습니다.
  • iOS / TextInput: maxLength가 0인데도 입력할 수 있던 문제를 수정했습니다.

다음 내용은 직전 정식 태그와의 공식 비교에서 확인한 내용입니다.

  • 직전 태그와의 비교에서 위 수정 항목과 내부 Podfile.lock·배포 버전 갱신을 확인했습니다. 태그 사이에는 총 15개 커밋이 있습니다.
